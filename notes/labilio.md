## **一、DevRel概述**

-   **定义**：DevRel（开发者关系）是连接产品/工程与外部开发者生态的桥梁，实现双向价值传递。
    
-   **组织模式**：
    
    -   独立DevRel部门：以生态增长为核心，决策响应快，易于调动资源。
        
    -   归属产研部门：技术理解深，与产品迭代对齐，直接影响SDK/API设计。
        

## **二、DevRel核心角色（10个）**

-   Developer Advocate（技术布道师）
    
-   Community Manager（社区经理）
    
-   Technical Writer（技术写作/信息架构师）
    
-   DevRel Engineer（开发者体验工程师）
    
-   Solutions Architect / Partner Engineer（解决方案架构师/生态伙伴工程师）
    
-   Ecosystem Growth Lead（生态增长负责人）
    
-   DevRel Program Manager（DevRel项目经理）
    
-   Developer Marketer（开发者营销）
    
-   Hackathon Lead（黑客松负责人）
    
-   DevRel Data Analyst（DevRel数据分析师）
    

## **三、DevRel在Web3中的四大角色**

1.  **倾听与反馈**：建立反馈渠道，进行竞品分析与用户调研，反哺产品迭代。
    
2.  **赋能与教育**：完善文档与教程，举办Workshop与培训，降低开发门槛。
    
3.  **生态与连接**：推动合作伙伴集成，建设开发者社区，促进资源流动。
    
4.  **影响与增长**：举办黑客松与大型活动，打造成功案例，扩大品牌影响力。

    -   Quick Start（快速入门）

## **一、Web3媒体的三大定位**

-   **信息分发者**：聚合行业前沿资讯、观点与数据，降低信息差，是圈内外用户接触Web3的“流量入口”。
    
-   **市场教育者**：面向新人解释基础概念、拆解协议机制、分析事件因果，帮助理解行业逻辑。
    
-   **价值发现者**：提供赛道热点、资金流向、社区动态等线索，帮助用户发现潜在机会，减少错过Alpha的概率。
    

## **二、Web3媒体 vs 传统金融媒体**

-   **时效性**：Web3是7×24小时全球市场，事件催化速度可达“秒级/分钟级”。
    
-   **信息来源**：更依赖链上数据、社区舆情、多渠道碎片信息，而非官方公告。
    
-   **核心挑战**：从海量噪声中快速剥离事实，建立自己的认知逻辑，避免信息过载。
    

## **三、记者日常工作流（以PANews为例）**

-   **晨会（9:30）**：团队分享前一日重要信息，筛选快讯或选题线索。
    
-   **选题与讨论**：记者自定选题 → 与主编讨论确认价值。
    
-   **信息收集**：多信源交叉验证，必要时进行采访。
    
-   **写作与审核**：撰写稿件 → 主编审核修订 → 发布（周期通常为1-2天）。
    

## **四、核心信息入口与工具**

-   **第一入口：Twitter (X)**
    
    -   信息最快、最活跃，是感知市场情绪与热点的关键渠道。
        
-   **第二入口：Telegram**
    
    -   项目方、交易所、KOL群组，信息密度高。
        
-   **数据与行情工具**：
    
    -   链上数据：Dune、Arkham、Nansen（付费）
        
    -   行情网站：CoinMarketCap、CoinGecko
        
    -   DeFi数据：DeFiLlama
        
-   **协作工具**：
    
    -   内部沟通与素材沉淀：Telegram + Notion
        
    -   写作与审稿：Google Docs
        
    -   AI辅助：ChatGPT（用于信息梳理、提问拆解，需核验来源）
        

## **五、事实核查与常见风险**

-   **核心原则**：Don’t trust, verify（多信源交叉验证）。
    
-   **常见陷阱**：
    
    -   AI幻觉导致信息失真
        
    -   假冒账号发布虚假融资/合并/名人发言
        
    -   情绪化内容误导判断
        
-   **取舍**：准确性 > 速度，宁愿不发也不发假新闻。
    

## **六、写作与采访要点**

-   **写作风格**：
    
    -   客观中立、准确简洁、故事性强
        
    -   善用类比、图表、分层解释，降低阅读门槛
        
-   **采访方法**：
    
    -   提前研究项目背景、数据、争议点
        
    -   提问避免技术堆砌，聚焦“技术带来的效果与价值”
        
    -   挖掘独家观点，避免PR化表达
        

## **七、AI的使用与边界**

-   **可用场景**：信息检索、问题拆解、素材初步整理
    
-   **不可替代的能力**：
    
    -   直觉与审美判断
        
    -   宏观叙事感知
        
    -   人际信任网络建立
        
-   **建议**：用AI辅助，但保持人类判断与表达训练。
    

## **八、入行建议与必备能力**

-   **个人IP建设**：

### 一、 核心思维：打破“打工”逻辑

-   **非线性成长**
    
    -   **拒绝资历崇拜：** Web3 不看重你在大厂拧了几年螺丝。**0.5 年的深度实战**（如深度研报、核心代码贡献）远胜过 3 年的平庸经验。
        
    -   **作品即名片：** 简历只是法律文件（建议压缩至 1 页），真正的敲门砖是你的 **GitHub PR (Pull Request)**、**推特 Thread** 或 **黑客松项目**。
        
-   **无许可精神 (Permissionless)**
    
    -   **不要等派活：** 这是一个“没有人给你发 offer 也能干活”的行业。直接去 Discord 贡献、去 GitHub 提代码、去发研报。你的每一次产出都在建立个人品牌。
        
-   **结果导向**
    
    -   执行力 > 学历/背景。关注那些“看不见的地方”（如链上数据、社区活跃度），而不是简历上的虚名。
        

### 二、 技能树与工具：如何“开挂”

-   **技术栈选择 (Dev)**
    
    -   **Rust：** 难度大，但在高性能底层（如 Solana）是刚需，稀缺性高。
        
    -   **Go：** 在交易所和后端开发中极为通用。
        
-   **学习“作弊”技巧**
    
    -   **AI 辅助：** 善用 **Cursor** 或 **Claude**。直接把 GitHub 上的开源项目代码丢给 AI，让它帮你拆解逻辑，比死磕文档快得多。
        
    -   **盯着钱看：** 对于非技术人员，学会看 **Etherscan** (链上浏览器) 和 **Dune** (数据分析)。分析资金流向和巨鲸 (Whales) 的动向，比看新闻靠谱。
        

### 三、 岗位真相：你在赚谁的钱？

-   **研究员 (Researcher) vs 媒体**
    
    -   **媒体：** 赚流量的钱，容易沦为工具人。
        
    -   **研究员：** 赚资本的钱。你的研报是写给 **LP (出资人)** 看的，要提供逻辑去辅助大资金做决策，而不是为了还要做“小编”。
        
-   **社区/运营 (CM)**
    
    -   **核心不是客服：** 不是简单的回答问题。
        
    -   **核心是情绪管理：** 管理 **FUD** (恐惧/不确定/怀疑) 情绪，在社区混乱中寻找共识。你要能处理用户的贪婪和恐惧。
        
-   **产品经理 (PM)**
    
    -   Web3 的 PM 重心不在 UI/UX，而在 **Tokenomics (代币经济学)** 和 **治理机制**。
        

### 四、 行业认知：这到底是怎样一个“局”？

-   **“毛坯房”理论**
    
    -   现在的 Web3 就像刚封顶的毛坯房，UI 差、体验烂。**但正因为乱，才有巨大的装修（增值）空间**。这时候进场是建设者，装修好了再来就是接盘侠。
        
-   **赤裸的搞钱驱动**
    
    -   这里的用户忍受度极高。只要你的产品能让他们赚钱（高 Yield），哪怕要在命令行里操作，他们也会挤破头去用。
        
-   **高风险与心态**
    
    -   **安全是底线：** 丢了助记词/私钥，一切归零。
        
    -   **抗压能力：** 行业波动极大，项目寿命可能很短。你需要有极强的心理素质面对归零和暴富。
        

### 五、 给新人的实操建议 (Next Steps)

1.  **别只顾着炒币：** 90% 的新人死于频繁交易。不做“韭菜”，要做“镰刀”或“卖水人”。
    
2.  **建立“长板”：** 别做全才。让自己贴上一个极度细分的标签（例如：“那个懂 Rust 安全的人” 或 “那个专门分析链上大额转账的人”）。
    
3.  **从小事做起：** 哪怕是翻译一篇高质量文档、修复一个 Typos，也是参与的开始。

### 核心心态

-   **Done is better than perfect**：一个有 Bug 但能跑完流程的项目，绝对优于一个写了一半的完美项目。
    
-   **评委视角**：评委不会看到深夜的代码，他们只看你呈现的故事。
    
-   **综合战争**：这不仅是技术比拼，更是产品、营销和心理的综合战。
    

### 倒计时 48H - 24H：

-   **功能止损**：没跑通 80% 的功能直接砍掉或合并。
    
-   **确立 Happy Path**：坐下来，画一条**绝对不会出得**的 Demo 演示路线。
    
    -   _案例_：连接钱包 -> 领取测试币 -> 购买 NFT -> 交易成功。
        
-   **Mock 数据策略**：
    
    -   如果后端数据没跑通，前端直接写死数据 (Mock Data)。
        
    -   遇到网络错误不要报错，直接“不处理”或显示模拟的成功状态。
        

### 倒计时 24H - 12H：

-   **前端 > 后端**：这是一个“看脸”的比赛。代码可以牛逼，但 UI 必须精美。
    
-   **前端“欺骗”**：
    
    -   即便后端挂了，前端 UI 也要显示“成功”，并在后台偷偷处理逻辑。
        
    -   一切为了 Demo 时的官感体验。
        
-   **预设测试账号**：
    
    -   准备 3 个以内的测试账号，提前在链上交互过，**有资产**，有历史记录。
        
    -   **切忌**：演示时现场领水（测试币）或现场注册，极易失败或排队。
        
-   **环境隔离备选**：
    
    -   如果公网测试网（如 Sepolia）突然拥堵怎么办？
        
    -   **备选方案**：准备一套本地节点 (Localhost/Hardhat)，一旦公网挂了，马上无缝切换到本地演示，评委看不出来区别。
        

### 倒计时 12H - 4H：

-   **视频录制是重中之重**：很多评委只看视频不看代码。
    
-   **视频脚本公式 (3分钟)**：
    
    -   **0-30s**：痛点是什么？（不念 PPT，要去讲故事）
        
    -   **30s - 2min**：录屏操作（加速处理签名等待环节，高亮鼠标点击位置）。
        
    -   **2m - 2m30s**：架构图（着重标出赞助商的 Logo）。
        
    -   **2m30s - 3min**：商业模式和后续开发计划。
        
-   **剪辑技巧**：如果代码跑不通，可以通过剪辑视频，把几段跑得通的代码拼接起来。
    
-   **README 装修**：
    
    -   这是项目的“门面”。
        
    -   必须包含：Logo、一句话 Slogan、演示视频链接、**测试网部署地址**、**测试账号和私钥**（方便评委自己玩）。
        

### 倒计时 4H - 0H：

-   **提前提交**：Devpost 等平台经常在截止前 10 分钟崩溃。
    
    -   策略：提前 2 小时创建项目页面，填写好 80% 的信息。
        
-   **合约验证 (Verify)**：
    
    -   确保智能合约在 Etherscan 上是 **Verified (已验证)** 状态，可以看到源码。
        
    -   **警告**：如果技术评委看到的是一堆乱码 (Bytecode)，会认为你不开源或有猫腻，直接扣分。
        
-   **多端测试**：
    
    -   发给朋友，让他用**手机**、用**无痕浏览**打开 Demo 链接。
        
    -   检查是否因为本地缓存或硬编码导致别人打不开。

-   **利用“逆康威定律”红利**
    
    -   **原理：** 系统架构受限于沟通结构。大厂因部门墙导致系统臃肿，而“一人团队”拥有零沟通成本的先天优势。
        
    -   **实战：** 作为独立开发者，你的大脑直接统管前端、后端与合约层，这能让你的代码架构展现出极高的一致性和紧凑性，非常适合快速构建 MVP（最小可行性产品）参加黑客松。
        
-   **角色重定义：从执行者 (Coder) 转变为管理者 (Leader)**
    
    -   **核心职能：** 你的工作不再是纠结语法细节，而是 `理解需求 -> 宏观规划 -> 任务分发 -> 方案评审`。
        
    -   **决策机制：** 遇到复杂问题时，负责将模糊的想法（Idea）拆解为具体的模块（Module），就像把商业战略拆解为部门KPI。
        
-   **建立“人机协作”的质检双保险**
    
    -   **AI 自检 (Self-Check)：** 强制 AI 在输出代码前进行自我反思（类似“审稿”），过滤掉因概率生成的幻觉和低级语法错误，作为第一道防线。
        
    -   **人工复核 (Double Check)：** 由你（Leader）进行逻辑审计。在 Web3 开发中，这特指检查智能合约的业务逻辑漏洞（如资产安全），这是防止“单点失败”的最后一道防线。
        
-   **将技术资源视为“人力资源”**
    
    -   **模型即员工：** 将不同的 AI 模型视为具有不同特长的员工（如 DeepSeek 擅长深度逻辑，Gemini 擅长快速处理长文本），根据任务类型灵活“派单”。
        
    -   **提示词即岗位说明书 (JD)：** 写 Prompt 的本质是下达清晰的指令。你需要明确定义 AI 在当前任务中的角色，而不是漫无目的地闲聊。
        
-   **模块化架构思维**
    
    -   **拆解策略：** 无论系统多复杂，都必须拆解为独立的积木。在 Web3 语境下，应明确划分为：`用户模块`、`支付模块`、`结算模块`、`AI Agent 模块`。
        
    -   **目的：** 模块化不仅降低了 AI 理解任务的难度，也方便你在某个模块出错时，快速进行单独替换或调试，而不影响全局。

### 🗨️ 核心范式转移：从租赁到拥有:

-   **资产所有权风险**：
    

**Web2 模式（租赁）**：用户仅拥有数据使用权。以《王者荣耀》为例，若腾讯倒闭，用户购买的皮肤将随之消失，资产本质仅是中心化服务器的一行代码 。

**Web3 模式（私有）**：实现真正的资产私有化。游戏道具（如屠龙刀）不再是运营商数据库里可随意修改属性的数据，而是用户的私有财产，可跨游戏使用或兑换法币 。

-   **服务运行逻辑类比**：
    
    **传统 App（小卖部）**：由“老板”控制。老板决定服务内容，且拥有随时“关门”（停止服务）的绝对权力 。
    

**DApp（自动贩卖机）**：放置于广场的自动化机器。一旦部署，无人能拔掉电源或拒绝服务，依靠代码逻辑自动运行 。

### 🗨️ 账号与数据体系重构

-   **登录方式变革**：从 `Register`（注册）转向 `Connect`（连接）。Web3 不再需要繁琐的注册流程，**钱包 (Wallet)** 即为万能钥匙兼身份证，且具备“插上即用，拔出数据带走”的特性 。
    
-   **数据主权分离**：
    
    -   **Web2**：前端与数据绑定。例如 TikTok 封号会导致内容归零 。
        
    -   **Web3**：前端只是数据的浏览器。以 Mirror 为例，即使网页前端消失，内容依然存储于链上，用户才是数据的主人 。
        

### 🗨️ 技术架构：DApp 的“三驾马车”

会议详细拆解了驱动 DApp 运行的三大核心组件 ：

1.  **智能合约 (Smart Contract) —— 裁判**：
    
    -   **功能**：铁面无私的裁判与执行者。
        

**逻辑**：`If Rain = True, Send Money to Alice`。一旦条件触发，自动执行，无需第三方介入（如 Web2 中间人），且一旦运行无法修改 。

1.  **区块链 (Blockchain) —— 账本**：
    
    -   **特性**：不可篡改、全公开。虽然用户身份匿名，但全球任何人的交易记录均为透明可查 。
        
2.  **代币 (Token) —— 燃料**：
    
    -   **Gas Fee (门票)**：支付给矿工的记账费，作为系统运行的成本 。
        
    -   **Governance (股票)**：代表参与 DApp 的治理权利 。
        

### 🗨️ 应用场景落地

-   **DeFi (去中心化金融)**：
    
    -   定义为“没有银行的银行”。无需 KYC（身份验证）、无银行审核、无注册。

    -   **角色转变**：用户可将资金放入资金池，自己做银行赚取手续费 。

## **Uniswap 工作原理解析**

### 🗨️ AMM 自动做市商

-   **传统模式：** 必须要有一个**卖家**挂单卖，有一个**买家**挂单买，
    
-   **Uniswap 模式 (AMM)：** 跟代码直接交易
    
-   Uniswap 不需要你在那里等别人接单
    

### 🗨️ LP 流动性做市商：

-   **问题：** 既然没有“卖家”，那我想买的币从哪来？
    
-   **答案：** LP，流动性提供者预先把很多币扔进了一个大池子里。
    
-   交易的本质，就是往池子里**扔进**一种币，**拿走**另一种币。

### 🗨️ 无常损失：

**定义：** **把币放在 Uniswap 池子里赚手续费**，虽然赚了手续费，但如果币价剧烈波动，你的总资产反而比直接把币拿着不动（HODL）要少。

**为什么叫“无常”（Impermanent）？**

-   因为这种损失是**暂时的**。
    
-   如果明天 ETH 的价格**跌回 100 USDT**，你的池子比例又会自动变回 1 ETH + 100 USDT。那 100 U 的损失就消失了，好像什么都没发生过一样。
    
-   **只有当把钱取出来的那一刻，这个损失才变成“永久”的。**

## 公共物品如何分配资金？

### 🗨️ 为什么我们要讨论“分钱”？

**在去中心化（Web3/DAO）的世界里，谁来决定把钱给谁？**

以前（Web2/传统世界）这事很简单，**委员会可以搞定，但是：**

-   **优点：** 快，效率高。
    
-   **缺点：** 权力太集中了。如果不认识委员会的人，好项目可能就拿不到钱；而且几个人也看不懂那么多复杂的提案。
    

* * *

### 🗨️ Web3 发明了什么新玩法？

**1\. 二次方资助 (Quadratic Funding, QF) - “人多力量大”**

-   **核心直觉：** 以前是“谁钱多谁说了算”（像股东大会），QF 是“**支持的人越多，匹配的钱越多**”。
    
-   **目的：** 削弱巨鲸（大户）的影响力，放大社区普通人的声音。
    
-   **存在的问题：** **女巫攻击 (Sybil Attack)**。因为看重“人数”，就有人疯狂注册假账号刷票。
    

**2\. 回溯性资助 (Retroactive Funding, RPGF) —— “先干活，后给钱”**

-   **最颠覆的点：** 以前找 VC（风投）拿钱是写 PPT 讲故事（画大饼），RPGF 是你先把东西做出来，产生了真实影响力，再给你发钱。
    
-   **案例：** Optimism (OP) 已经发了快 1 亿美金了。
    

* * *

### 🗨️ 新趋势：AI 也能当“评委”

随着项目越来越多（一轮几百个），纯靠人眼看根本看不过来。

-   **AI 的作用：** 不是直接替人做决定，而是打辅助。
    
    -   先把数据“提纯、聚类、排序”（比如把类似的去中心化社交项目归一类）。
        
    -   最后还是由人类（陪审团）做最终拍板。
        

* * *

### 🗨️ 课后互动：“分配博弈”游戏

-   **设定：** 大部分是好人，但混进了 20% 的\*\*“治理攻击者”\*\*（坏人）。
    
-   **坏人的目标：** 搞小团体、甚至贿赂，把钱全导向自己的那个烂项目。
    
-   **好人的目标：** 保持理性，把钱投给真有价值的项目。
    

**其他：**

1.  **治理攻击是真的存在的！** 在利益面前，真的有人会暗箱操作。
    
2.  **“随手投”也是一种作恶。** 课件里叫“治理冷漠”。如果不认真看提案就瞎投平均分，其实就是把阵地拱手让给了坏人。
    
3.  **会说话真的很重要。** 哪怕项目再好，如果讲不清楚逻辑，就没法在大战中获得共识。**专业性 + 话语权 = 影响力。**
    

-   **QF** 解决了大户垄断问题，但怕假人。

### 🗨️ Twitter Space 活动策划

![image.png](attachment:45cf0f47-fe8a-4fdb-a285-1f9b4d38fc0d:image.png)

**1\. 筹备阶段**

-   **拟定问题库：**针对主题进行调研，准备嘉宾问答提纲。
    
-   **确定主题与目标人群：**如“以太坊十周年”或热点话题“AAVE”。
    
-   **邀请嘉宾：**
    
    关键信息收集：嘉宾姓名、推特 Handle、Title（所属组织/项目）、头像。
    
    邀请话术：需包含主题、时间、拟讨论话题，确保信息明确精简。
    
-   **创建筹备群聊：**提前建立嘉宾专属群，用于信息同步与材料确认。
    

**2\. 宣传物料准备**

-   **海报设计**：包含主题、时间、嘉宾信息等。
    
-   **宣发文案**：需包含主题、时间、嘉宾名单、Space 链接。
    

**3\. 宣传节奏**

-   **提前 2–3 天**：发布海报与文案，全渠道分发（推特、社群等）。
    
-   **活动当天/前一天**：再次提醒，强化记忆。
    
-   **开始前 5–10 分钟**：最后提醒，提升即时参与率。
    

**4\. 现场执行流程**

-   **开场环节**
    
    1.  主办方品牌介绍。
        
    2.  嘉宾自我介绍（重视个人品牌露出）。

-   **核心环节**：按问题库进行嘉宾问答，主持人需灵活应对（如问题已回答则调整顺序）。
    
-   **可选环节**：观众提问互动。
    

**5\. 活动复盘**

-   **关键数据指标**
    
    -   **推文浏览量**：评估前期宣传覆盖度。
        
    -   **Space 实时在线人数**：最核心指标，反映活动真实热度（警惕“买粉”造成的虚假人数，可通过头像展示区初步判断真实性）。
        
    -   **总收听人数（Tuning）**：次要指标，因重复进入会被重复计算。
        
-   **优化记录**：记录执行中的问题与改进点，用于迭代优化。

## AI和WEB3 — 基本介绍和SpoonOS的介绍

### 🗨️ 过去的痛点：

1.  没有记忆：聊了半天换一个窗口就没了
    
2.  信任危机：
    
    1.  不知道操作的人是**真的人还是机器人**
        
    2.  不知道机器人是**正规机器人还是黑客**
        
    3.  日志可以篡改（不能追责！）
        
3.  收费：订阅模式不能做微支付
    

![image.png](attachment:cfcbf808-a997-4730-8312-7a14c343bc95:image.png)

### 🗨️ 解决办法：用区块链技术解决 \[日志可以被篡改\] 和 \[没有原生账本\] 的问题

1.  区块链相当于把这个 AI 智能体的所有“行为日志”和“身份信息”刻在链上
    
    -   **身份锚定：** **ERC-8004** 就像给 AI 发了一个无法伪造的身份证。
        
        -   这个\[ERC-8004\]是一个以太坊基金会提出的**AI智能体共识**
            
    -   **行为留痕：** AI 做过的每一笔交易、每一次交互，都会在链上留下痕迹
        
2.  **什么是“原生账本”？**
    
    1.  AI 智能体自己就是一个独立的“经济人”。
        
    2.  它拥有自己的钱包地址（公钥）和私钥，它**不需要去银行柜台排队填表（KYC）**
        
    3.  它生来就在区块链这个“账本”上拥有一个位置。
        
3.  有什么用？
    
    -   工作留痕：有问题可以追责
        
    -   ChatGPT不能帮你买机票，因为他没有原生账户。现在有原生账户，AI可以自己交易

## 课程内容 Bruce - 基础知识

### 🗨️ 前置常识

1.  同一组助记词可以生成出**无限个私钥**，所以私钥不是唯一的。是**一对多**的
    
2.  冷钱包的原理：私钥 + 转账申请 → 合成一个\[签名\]
    
    1.  签名可以用来广播，也就是发送交易申请了
        
    2.  验证者（矿工）可以判断，这个签名是不是私钥发的，还是乱发的
        
    3.  所以不容易伪造
        
3.  Gas费不是手续费，不是固定的。Gas费可以自己手动调高
    

### 🗨️ RPC和中心化风险

1.  你的钱包 = 手机银行App
    
2.  **RPC服务 = 快递员/信使**
    
3.  问题：如果这个\*\*快递员RPC是唯一的，\*\*那么一旦他倒台了就完蛋了
    
    1.  整个去中心化的系统，在“最后一步”依赖了一个中心化的服务商
        
    2.  RPC服务也要去中心化，不能鸡蛋放要给篮子里
        
4.  解决方案：**多准备几个RPC**
